## Problem and scope

The v0.3.18 Plugin Store artifact installs only the dynamic plugin. Its
plugin-pages wrapper still loads the browser-facing `/agent-identity/` sidecar
dashboard. Deployments without that reverse proxy show “Codex Agent Identity
temporarily unavailable” even when CPA can reach the sidecar privately.

This candidate:

- embeds the complete management page, JavaScript, styles and theme bridge in
  `codex-agent-identity.so`;
- adds an authenticated CPA Management API bridge from that page to the private
  sidecar;
- keeps `/agent-identity/` only as an optional compatibility fallback;
- leaves CPA native OAuth ownership, PAT execution, stored identities and the
  sidecar data plane unchanged.

The Plugin Store still cannot create the sidecar container, Docker network,
Management/encryption keys or persistent data directory. A separately deployed
sidecar and private CPA-to-sidecar route remain required.

Current stock Management Center does not expose its in-memory login key to
plugins when Remember password is unchecked. The embedded page then shows a
manual authentication form; it does not scrape the parent application state or
force password persistence. Remembered matching-scope credentials can be reused.

## Follow-up debug before release

The production installation was independently observed serving the v0.3.18
wrapper, with no `/ui` route and no production sidecar. A separate stock CPA
v7.3.0 canary confirmed that the embedded page and private API bridge work.
Real Management Center browser checks uncovered the unremembered-session
authentication state. The candidate now shows manual authentication after the
bridge timeout and rejects stale iframe or mismatched legacy credentials.
Tests execute the generated JavaScript with bounded subprocess deadlines and
cover these transitions. The embedded mobile view reserves space for the stock
Management Center's floating toolbar; standalone and desktop spacing is unchanged.

`.github/scripts/debug-plugin-install.py` checks the exact installed version,
optional file checksum and Linux Docker process-mapped library checksum,
embedded resources, authenticated identity/diagnostic
reads and sidecar-to-CPA synchronization. Negative checks run only in an isolated
canary. The script never imports accounts or calls quota-reset endpoints.

## Deployment evidence and correction

- Successful rollout: `2026-09-14T11:11:23Z`; read-only recheck at
  `2026-09-14T11:35:54Z` remained healthy.
- CPA kept its stock `eceasy/cli-proxy-api:v7.3.0` image and original image ID.
  Other installed plugins, auth files, ports and unrelated containers were
  preserved. Existing sidecar encryption/management keys were reused.
- The actual production CPAMC menu opened the embedded page. Remembered login
  credentials connected automatically; an unremembered session displayed the
  manual form and connected after entry. Both browser runs had zero page
  errors or failed HTTP responses. At 390px width, the title was clear of the
  floating toolbar and there was no horizontal overflow.
- The private sidecar was healthy and CPA synchronization was ready. No
  credentials were imported and no quota reset was performed.

The first rollout at `2026-09-14T10:32:20Z` was **not successful**. Its deployment
script assumed old plugin files would stay beside the new version. Stock CPA
cleaned up the unselected old Agent Identity library on its writable mount,
which triggered a missing-file verification error. The initial rollback
restored configuration and removed the new library without restoring the old
one, leaving Agent Identity unregistered while CPA and the other plugins ran.

The old library was restored from the checksum-verified immutable v0.3.18
archive, and registration plus all original plugin hashes were independently
verified. Before retrying, a writable-mount canary reproduced cleanup and
passed upgrade, externally backed-up rollback, and re-upgrade. The corrected
deployment backs up every original plugin outside the discovery directory and
restores the old Agent Identity library before restarting during rollback.
No source tag or Release asset was replaced to correct this host-side script.

Rollback target: the existing immutable v0.3.18 release and its retained
deployment backups. No live reset-credit consume/redeem call is permitted as a
validation step.
