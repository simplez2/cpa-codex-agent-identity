## 正式资产联合验收

同主机隔离部署官方 `eceasy/cli-proxy-api:v7.2.152`、正式 v0.3.18 `.so`
及正式镜像，使用独立 auth/config/加密存储和随机测试密钥。

验收期间生产账号配置了新代理，原无代理脚本在发请求前停止。后续全新
导入沿用当前账号 SOCKS5h 出口；受限、认证的 HTTP CONNECT 测试代理也
串联该出口，未绕过当前代理。没有清空或覆盖生产账号的代理设置。

| 验收 | 结果 |
| --- | --- |
| 正式插件注册、启用、报告版本 0.3.18 | 通过 |
| 全新导入 PAT 为原生文件；不含桥接/运行时/旧过期字段 | 通过 |
| WS=false、停用、代理、备注、优先级经历刷新和 CPA/sidecar 重启 | 全部保留 |
| 原生启用后落盘和重启 | 通过 |
| 认证代理下原生额度 | HTTP 200，代理确有连接 |
| WS 关闭，客户端仍发 WS | 上游 HTTP POST=1、WS=0，文本且完成 |
| WS 开启，同会话两次请求 | 上游 WS=2、握手=1、响应帧=24、HTTP POST=0，均完成 |
| 拒绝连接的 SOCKS 代理 | 模型、额度、冷启动凭证验证均失败，没有直连回退 |
| 恢复当前账号出口，仅重启隔离 CPA 清除测试冷却 | HTTP 200，文本且完成 |
| 生产源凭证未改动、临时容器/日志清理 | 通过 |

PAT 验证元数据会缓存，暖缓存下的同步成功不是“重新访问上游”的证据；
坏代理验证特意重启隔离 sidecar 后再测，不把缓存命中误判为 IP 泄露。

## 生产切换与复验

- 切换前停止旧同步器，备份当时的 auth、加密存储、CPA 配置和 Compose；
  私有备份保留用于回滚，不上传仓库。旧插件和镜像保留。
- 五个 PAT 的凭证、Team、代理、启用状态、WS、优先级、备注和路由字段
  与切换前逐项相符；过时 sidecar 投影字段已移除。
- 仅更新 Agent Identity 插件/镜像；CPA 为加载 `.so` 短暂重启，但镜像
  不变。Keeper 镜像、容器 ID 和启动时间不变。
- 线上插件版本 0.3.18，已注册且生效；sidecar / Keeper 均 healthy。
- 默认 luna HTTP 流：200，文本、finish、[DONE] 完整，2.924 秒。
- 原生额度：HTTP 200。
- 默认 WS：101，文本且 `response.completed`，首字 1.985 秒、全程
  2.061 秒；同会话 ID 匹配官方上游 WS connected 日志。
- Smoke 测试前后生产 auth 文件字节不变。

时间为服务器侧单次观测，不是性能保证；未逐一验收每个账号的故障切换。
JWT/AgentAssertion 的完整原生能力、任意用户代理及未来 CPA 功能不在此
验收结论内。商店只安装 `.so`，仍需已部署 sidecar 和加密持久化存储。
